# Tests

`tests/test-<name>.*` covers the script of that name, named after the script, not its file (`test-atuin-login.sh` covers `atuin-login`, `loadouts/atuin/.loadout/login.ts`); a few cover more: `test-tmux-plugin.zsh` also covers `tmux-ensure-server` and `tmux-server-cwd`, and `test-machine-data.sh` the templates' use of the `loadout/machine` partial (it builds `.chezmoi-home/` with a loadout command first). `vm-new-machine.sh` isn't one of them: it sets up a whole machine in a VM (its header says how). After touching one of these, run its test and extend it to cover new behavior; a new script in the same spirit gets a sibling test. Cosmetic changes (comments, icons, wording) need none. These scripts have shipped silent regressions before (an empty picker icon, a bash-4-only builtin on bash 3.2, a popup hijacking the wrong client, zsh's read-only `status` breaking error handling), so treat them as production code.

How they're written:

- Most bash tests of the tmux scripts (`test-tmux-*.sh`) source the script under test (each has a `BASH_SOURCE` guard so sourcing doesn't run its entry point), shadow `tmux()` to send its calls to a throwaway socket, and assert against real tmux and git state. `test-tmux-workmux-open.sh` runs its script as a process instead, with fake `tmux` and `workmux` on `PATH` that log their arguments.
- The tests of loadout scripts (`test-atuin-login.sh`, `test-android-sdk.sh`, `test-omarchy-brave.sh`, `test-bare-repos.sh`, `test-github-ssh-key.sh`, `test-t2-bcm-firmware.sh`) call the module's `check` or `install` as loadout does, through `loadout bun tests/run-module.ts <module> <function> ['<options>']`, against fakes on `PATH` or local fixture repos and a throwaway `$HOME`; a script that reads fixed system paths takes a prefix for them from the environment (`T2_BCM_FIRMWARE_ROOT`).
- The zsh plugin tests run the directly-sourced plugin in a fresh `zsh -c` per case, with `$HOME` and `$PATH` pointed at a throwaway fixture (fake `workmux`, `chezmoi` and `gum` binaries that log their arguments). `test-tmux-plugin.zsh` instead runs the real tmux on servers of its own via `TMUX_TMPDIR`.
- `test-dotfiles-worktree-check.sh` runs the real `chezmoi` against a fixture `$HOME`, source and worktree in one `mktemp` dir (a fake `loadout` hands the script's `loadout --repo <dir> chezmoi …` to it as `--source <dir>`).
- Prefer a real dependency over a fake when it's safe (`test-workmux-plugin.zsh` uses the real `gum`).
- Run a test the way its shebang says (`zsh` for `.zsh`), never `source`d into the current shell: this environment's shell is zsh, where a bash script can misbehave silently instead of failing.
