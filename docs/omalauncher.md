# omalauncher

`omalauncher-galaxy-a56` is Arch inside the omalauncher Android launcher (profile `machines/profiles/omalauncher.profile.loadout.hcl`, data flag `omalauncher`; `bootstrap.sh` sets it up, branching on that flag, read from `loadouts/.chezmoidata/loadout.json`; after changing it, compare `--dry-run` for a desktop machine before and after: the same output). It's proot as root: no systemd, the rootfs ships without sudo, and every process start costs ~9ms, so a tool that forks per prompt is felt (starship ~200ms, `mise activate`'s hook ~270ms, `git status` ~230ms). Port only what it needs, and track all of it in the loadout; nothing of the desktops' toolchains goes there (mise holds its tools, in `loadouts/private_dot_config/mise/conf.d/omalauncher.toml`).

- **Its files**: `.chezmoiignore` gives it only its own files (the phone's block there lists them) and keeps all of them off every other machine. After touching those rules, compare `chezmoi managed` for each desktop (`--override-data '{"chezmoi":{"hostname":"<machine>"}}'`) against `master`: it must not change.
- **The launcher's files go phone -> repo**: they're edited on the phone (by hand, by agents, and by the launcher, which rewrites `layout.toml` as tiles move), so `omalauncher-tracked` (`loadouts/private_dot_config/private_omalauncher/.loadout/tracked.sh`) adds new ones, re-adds changed ones and forgets deleted ones, and `loadout apply` never pushes the repo's copy back over a phone edit. Run it before `loadout sync`, which refuses edited files. The widgets folder's `.claude/settings.json` runs it as a hook on every Claude Write or Edit there, and its `AGENTS.md` holds the rules for agents that start in it. A widget's packages live only in its `requires { pacman: [...] }`; `omalauncher-requires` installs what those declare, so they're never also listed as programs.
- **Sessions without tmux or workmux**: neither runs there. `start-dotfiles-change` (`loadouts/.chezmoitemplates/start-dotfiles-change`, rendered into both zsh configs' `functions/`) runs claude in the terminal instead of a tmux session, continues the folder's conversation when run again, and removes the try folder after claude exits once the session leaves `.claude/finished`. Feature worktrees there are plain `git worktree add` (where workmux would put them), merged with `git merge --ff-only` and removed with `git worktree remove` after `dotfiles-worktree-check`; the session's `AGENTS.md` (`NEW-LOADOUT-SESSION-AGENTS.md.tmpl`) says how. The phone's branches in those templates are `omalauncher` ones; after changing them, render each desktop against `master` (`chezmoi execute-template --override-data …`): byte for byte the same.
- **Its name**: chezmoi reads `/etc/hostname`, and loadout's gethostname says `localhost` under proot, so loadout gets the name from `LOADOUT_MACHINE` (zsh-omalauncher's `.zshenv`; `machine-name` keeps `/etc/hostname` and `~/.bashrc` in step). A new install writes `/etc/hostname` before the first `chezmoi apply`, or it gets the desktops' configs.
- **sudo**: the built-in `pacman` installer runs `sudo pacman` and requires the `sudo` program, which `install-sudo.sh` installs as root. loadout asks for sudo before any plan with a sudo step, so a new install runs `loadout install sudo` first.
- **zsh-omalauncher**: no plugin manager, no starship, nothing forked at startup (once its caches exist) or at a prompt; completion and the plugins (Arch packages) load after the first prompt. It shares ../zsh's snippets through chezmoi `include`, so a change there reaches it. Time a change with `zsh -i -c exit` (~90ms; bare zsh is ~55ms) and try it in a pty (`script`), where zle runs.
- **The launcher's own**: `fakeroot-shim` stands in for fakeroot (SysV IPC, which Android kernels lack; checkupdates needs it). Links open in the Android browser through the launcher's `/usr/local/bin/xdg-open`, so never set `BROWSER`. `/usr/local/bin/yay` is the launcher's wrapper: as root, any call (even `-Ss`) first runs `pacman -Syu base-devel git`; don't run it without asking.
