# Machines and profiles

- One file per machine in `machines/`, named by its hostname (`machines/t2-macbook-omarchy.loadout.hcl`); one per profile in `machines/profiles/` (`omarchy.profile.loadout.hcl`: `.profile` keeps the name apart from a tool's); `machines/profiles/shared.loadout.hcl` holds the `locals` several profiles use (`everyday_cli`, `shell_scripts`; no `.profile`: it's not one). Each machine's state is `machines/state/<machine>.json`, written by loadout.
- A profile holds what machines of a kind share; a machine is a real host that `extends` profiles, sets `data`, and overrides its profiles. Two profiles of one list disagreeing is a compile error.
- Programs with several ways to install go in one `via "<installer>" { install = […] }` block per installer, holding every program the profile installs that way, single-variant ones included. Outside a block go only programs with one variant and named variants (`variant(program.setup-brew, "linux")`). A shared local still sits in the block of the installer that moves it.
- A script with arguments is `args(script.x, "a", "b")`, one argument per line. A profile's long list can be a user function beside the scripts it configures, called from the profile's `run` (`omarchy_bar()` in `loadouts/private_dot_config/.omarchy/.omarchy-shell.loadout.hcl`; `ssh_key("t2")` in `loadouts/.ssh/`).
- A machine is named by its hostname, except one whose hostname isn't its own to change (the work laptop's): it names itself in `~/.config/loadout/machine`, and a child repo's machine names that repo's checkout in `~/.config/loadout/repo` (in no repo; `bootstrap.sh <machine> --child <ssh url>` writes both). `~/.config/zsh/.zshenv` exports them as `LOADOUT_MACHINE` and `LOADOUT_REPO`, not `~/.zshenv`, which a zsh that inherits `ZDOTDIR` (a tmux pane) never reads.
- Adding a machine: the README's "New machine".
